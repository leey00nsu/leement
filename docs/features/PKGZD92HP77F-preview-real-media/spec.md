# Feature Spec: preview-real-media

## 개요

- **기능 ID**: PKGZD92HP77F
- **기능명**: preview-real-media
- **대상 레포**: Leement
- **작성일**: 2026-10-07
- **상태**: Approved

## 목적

현재 Preview에는 사진 자리를 대신하는 회색 SVG와 직접 그린 풍경, 도형을 움직이는 영상, 생성한 톤 음원이 사용된다. 이미지·영상·음악을 보여주는 자리를 전수 점검하고, 용도에 맞는 Pixabay의 실제 무료 미디어로 바꿔 컴포넌트의 실제 사용 모습을 보여준다. 콘텐츠와 제목·대체 텍스트·포스터도 함께 맞추고 정상 표시와 재생을 검증한다.

## 검수 범위

- 제품 기준 revision: `31642301cb61a9432094c7af95863fea489d676f`.
- 초기 소스 조사: examples / registry blocks / UI / patterns의 TSX 872개 중 미디어 신호가 있는 73개 파일, 로컬 데모 자산 11개. 그중 14개 파일에 inline SVG 대체물이 있고 17개 파일이 직접 그린 데모 자산을 참조한다. 목록과 줄 번호는 [media-audit-scope.json](./artifacts/media-audit-scope.json)에 있다.
- 이 수치는 검색 후보 목록이며 전수 화면 검수 완료 수치가 아니다. JSX, CSS background, 상수·간접 참조, 기본 props, 상세 Preview·Showcase·Usage·복사 코드에서 발견한 미디어 자리를 목록에 보강한다.
- 이미지: AspectRatio, Card, Attachment, Avatar, Sidebar, Message, Crop, Zoom, Comparison, Glimpse, MediaReveal, Stories와 해당 변형·조합.
- Blocks: About, Blog, BlogPost, Feature, Team, Testimonial, Changelog 및 CaseStudies·CaseStudy·Form 등에서 사진 props나 표지 사용을 실제로 보여줘야 하는 예제. 기본 props의 대체물과 사진 예제가 빠진 구성도 확인한다.
- 영상: VideoPlayer, Hero, Stories, Reel의 영상·포스터·소스 변경. 가로 영상과 세로 Reel에 각각 적합한 프레이밍을 사용한다.
- 음악: AudioPlayer의 실제 곡, 파형, 재생·탐색·소스 변경·실패 복구.
- 기존 외부 사진·아바타도 함께 점검한다. 일반 데모 콘텐츠는 Pixabay에서 선정하고, 실제 작성자 정체성을 나타내는 이미지나 정상적인 의미가 있는 자산은 용도를 근거로 유지 여부를 기록한다.

## 사용자 스토리

### US-1: 실제 콘텐츠로 구성된 미리보기

**As a** Leement 사용을 검토하는 개발자
**I want** 사진·영상·음악이 들어간 현실적인 예제를 보고
**So that** 실제 서비스에서의 표현과 조작을 판단할 수 있다.

**Acceptance Criteria:**

- [x] 초기 후보와 추가 발견 자리마다 교체·유지·해당 없음 판정과 이유, 연결된 Preview를 기록한다. 미검수 자리나 설명 없는 대체물을 남기지 않는다.
- [x] 정상 상태의 사진 자리를 회색 SVG, 도형 풍경, 생성한 임시 프로필 그림으로 채우지 않는다. 실제 Pixabay 사진을 사용하며 같은 인물은 일관되게, 서로 다른 인물·기사에는 구별 가능한 콘텐츠를 제공한다.
- [x] 제목·설명·대체 텍스트·작성자·포스터가 실제 콘텐츠와 맞는다. 자연 영상을 제품 시연이라고 부르거나 외부 미디어를 Leement 자체 제작이라고 표시하지 않는다.
- [x] 아이콘, 브랜드 마크, 차트, 코드·QR, Skeleton, 빈 상태와 의도적인 오류·fallback 예제는 본래 역할을 보존한다. 로고·인증 배지를 무관한 사진으로 바꾸지 않고 적절한 데모 마크로 구성한다.
- [x] 스톡 인물을 실제 직원·고객이나 제품 추천자로 오인시키지 않는 샘플 맥락으로 표시한다.

### US-2: 실제 미디어를 조작하는 예제

**As a** 미디어 컴포넌트를 평가하는 개발자
**I want** 실제 영상과 음악을 재생하고 조작하며
**So that** 정상 동작과 실패 복구를 함께 확인할 수 있다.

**Acceptance Criteria:**

- [x] 영상의 실제 로드·재생·일시 정지와 재생 시간 증가를 확인한다. 지원하는 탐색, 음소거·음량, 소스 변경이 동작한다.
- [x] Reel은 9:16에 적합한 실제 영상으로, Stories는 전환·종료 시 미디어를 정리하며, 포스터는 해당 영상의 장면을 보여준다.
- [x] AudioPlayer는 실제 음악으로 재생·탐색·파형·소스 변경을 보여준다. 초기 진입에서 음악을 자동 재생하지 않는다.
- [x] 오류·초기화·native fallback, Replay, 닫기와 src 변경 시 재생 정리, reduced motion 및 SSR 안전성을 유지한다. 자막·설명도 실제 콘텐츠에 맞추며 기존 도형 영상의 자막을 재사용하지 않는다.

### US-3: 출처와 사용 조건을 추적할 수 있는 무료 자산

**As a** 예제 소스를 사용하는 개발자
**I want** 미디어의 출처와 사용 범위를 확인하고
**So that** 소스를 재사용할 때 실제 콘텐츠의 조건을 알 수 있다.

**Acceptance Criteria:**

- [x] 자산별 Pixabay 원본 페이지, 제작자, 확인·다운로드 날짜, 적용 라이선스, 원본·변환 파일의 해시·크기, 화면 비율·재생 길이와 사용 위치를 추적한다.
- [x] 무료 항목을 선정하고 유료 광고 결과를 제외한다. 실제 촬영 사진·영상을 우선하며 사람이 찍은 콘텐츠처럼 보이는 AI 생성물로 문제를 대체하지 않는다.
- [x] 코드의 MIT 라이선스와 미디어 라이선스를 구분한다. CC0는 게시 날짜와 해당 약관 근거를 보존하고, 그 외에는 docs·공개 저장소·registry 각각의 제공 방식이 사용 조건에 맞는지 확인한다.
- [x] 원본 음악 등의 단독 재배포 금지를 지키는 제공 방식을 확정한다. 사용 조건이 맞지 않는 후보는 다른 적합한 Pixabay 항목 또는 허용된 제공 방식으로 해결하며 미확인 후보를 완료 처리하지 않는다.
- [x] 음악의 Content ID 여부와 필요한 사용 증빙을 확인한다. 표시가 없다는 이유만으로 등록이 없다고 단정하지 않는다.

### US-4: 왼쪽 메뉴의 알파벳순 탐색

사용자가 추가 요청한 대로 Components·Blocks·Patterns의 왼쪽 메뉴에서 기존 기능 분류 안의 항목을 표시 이름 기준 A–Z로 정렬한다. 같은 navigation 데이터를 사용하는 모바일 메뉴에도 적용하며 현재 항목 선택과 링크를 유지한다. 범주 데이터 순서는 Components → Blocks → Patterns로 맞춘다.

**Acceptance Criteria:**

- [x] 세 범주 각 분류의 실제 desktop/mobile 메뉴 항목이 표시 이름 기준 알파벳순이고 현재 항목·링크가 유지된다.

## 기능 요구사항

### FR-1: 용도에 맞는 전체 미디어 선정

각 미디어 자리의 역할, 비율, 크롭, 읽기 맥락에 맞는 사진·영상·음악을 연결한다. 업무·인물·기사 표지·이미지 편집·미디어 피드에 필요한 구분을 제공하고 하나의 풍경을 모든 용도에 반복하지 않는다. Comparison은 같은 원본의 의미 있는 편집 전후 또는 설명된 비교 쌍으로 구성한다. 현재 [Pixabay 후보 목록](./artifacts/pixabay-candidates.json)의 7개 항목은 공식 페이지 메타데이터를 확인한 초기 후보이며 최종 선정이나 다운로드·시청·청취 완료를 뜻하지 않는다.

### FR-2: 안정적인 예제와 설치 계약

런타임 검색 API나 API 키 없이 안정적인 경로와 용도에 맞게 최적화된 자산으로 표시한다. 예제의 Preview·복사 코드·Usage·API 설명이 일치해야 한다. registry 설치 결과가 docs 전용 public 경로에 암묵적으로 의존하지 않도록 하며 기존 public props·exports와 앱이 미디어를 소유하는 계약을 유지한다. 실제 미디어를 명시적으로 전달하는 데모 조합을 우선한다.

### FR-3: 표시와 정상 재생 검증

변경된 모든 독립 Preview와 변경된 기본 props의 소비 화면을 확인한다. light/dark, 좁은 폭(390px)·넓은 폭(1440px)에서 실제 이미지 디코딩과 크롭, 포스터 및 영상·음악 재생을 검증한다. Crop·Zoom·Comparison·Reel·Stories·AudioPlayer·VideoPlayer 등 조작이 중요한 항목은 필요한 키보드·240px·소스 변경·오류 복구도 확인한다. 실제 OS의 reduced motion 확인과 제한된 합성 환경 확인을 구분한다. 미디어 변경 뒤에도 기존 inset·폭 조절·Replay·Foundation 동기화·lazy loading을 보존한다.

### FR-4: 유지 가능한 자산 기록

Feature에 전수 검수 결과와 검증 근거를 남기고, 프로젝트의 미디어 출처·라이선스 안내 및 필요한 자산 제공 방법을 동기화한다. PRD의 실제 예제 요구사항과 앱이 미디어를 소유하는 규칙에 영향을 평가한다. 기존 README 수정은 이번 범위에 포함하지 않는다.

## 비기능 요구사항

- **성능**: 표시 크기에 맞는 이미지와 썸네일·포스터를 제공하고 모든 예제에서 원본 4K 영상을 선행 로딩하지 않는다. 레이아웃 크기를 안정적으로 유지하며 구체적인 크기 예산은 승인 후 Plan에서 정한다.
- **접근성**: 의미 있는 대체 텍스트와 장식 이미지의 빈 alt, 이름 있는 재생 컨트롤, 실패 복구와 키보드 조작을 유지한다.
- **출처**: 파일과 설명이 실제 제작자·콘텐츠·적용 라이선스에 맞고 초상·상표 등 해당 권리 조건을 확인한다.
- **호환성**: 타입 검사, lint, 기존 관련 테스트, docs·registry 빌드와 독립 소비자 검사를 수행한다. 신규 영구 테스트는 승인된 Verification Contract에서 필요한 회귀 동작에 한해 정한다.

## 제외 범위

스톡 검색 서비스나 미디어 엔진 신설, UI 디자인 재설계, 실제 조직·고객 관계의 조작, 유료 미디어 구입, 백엔드·인증 추가, README 변경, 원격 push·공개 배포는 포함하지 않는다.
