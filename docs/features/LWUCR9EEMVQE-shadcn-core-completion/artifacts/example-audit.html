현재 미병합 Feature worktree; UI79의 public source API·registry·metadata·예제와 렌더링 경로를 정적 대조. Pattern15/Block8은 추가 조사. 이번 분석에서는 실제 브라우저 전수 조작/접근성/시각 검증을 수행하지 않음.

공통 원인

ItemPage→ItemWorkbench→Preview(name)로 대표 예제 하나를 렌더하며 getItemCode는 examples/name.tsx 한 파일만 읽는다. Variants/Sizes/States는 별도 live example이 아니라 설명 문장. Showcase도 같은 예제 전체를 mount한다.

개선 방향

  1. Showcase에는 가벼운 대표 예제 하나를 유지한다.
  2. 상세 페이지에는 이름·설명·각 예제의 Code/Preview를 갖춘 Examples 섹션을 둔다.
  3. Example source를 중복하지 않고 catalog에서 showcase 기본예제와 상세추가예제를 참조한다.
  4. 실제 registry 원본을 import하고 지원하지 않는 upstream 기능을 예제 범위로 섞지 않는다.
  5. 서버 저장·파일 처리·비동기 결과는 앱 조합임을 명확히 표시한다.
  6. 전체 조합의 곱집합을 만들지 않고 기본/중요변형/상태/조합 중 필요한 것만 보강한다.
